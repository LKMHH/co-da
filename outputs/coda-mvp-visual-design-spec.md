# CODA｜现场工作助手 MVP 高保真视觉设计稿

> 文档状态：视觉稿 v1.1（冻结修订）
> 
> 产品基线（v1.0，不修改）：`outputs/electrician-workbench-mvp-product-design.md`
> 
> UI 基线（v1.1）：`outputs/coda-mvp-ui-design-spec.md`
> 
> 技术基线（v1.1.1）：`outputs/coda-mvp-technical-design-draft.md`

本稿只调整视觉表现、布局、组件和交互呈现，不修改产品范围、业务状态、数据规则或技术接口。所有状态、字段、入口和文案均以产品 v1.0 与 UI/技术 v1.1 基线为准；技术稿未定义的动作在文末列为“待技术确认”，不在本稿中发明新 UseCase。

## 0. 设计结论

- 目标用户是需要戴手套、单手操作、在低注意力环境下快速留下记录的现场电工。首屏优先“现在要做什么”，设置和低频维护后置。
- 视觉采用浅色、低装饰、强层级的 Material 3 语义。用深色文字和结构分组保证可读性，用颜色辅助状态但不独立表达状态。
- 所有表单页保留固定底部操作区；滚动内容只在上方变化。键盘、系统字体放大和长文案不会挤掉主按钮。
- 故障处理状态和恢复结果分两行显示。例如“已结束｜未恢复”，不能用“已结束”替代“设备已恢复”。
- `CANCELED` 是可见业务终态；`VOIDED`/`voidedAt` 只表示隐藏作废。作废入口和取消入口始终分开。

## 1. 整体视觉方向

### 1.1 颜色令牌

| 令牌 | 色值 | 视觉用途 | 约束 |
| --- | --- | --- | --- |
| `surface.page` | `#F6F7F9` | 页面底色、滚动背景 | 不使用渐变 |
| `surface.content` | `#FFFFFF` | 表单区、列表区、底部操作区 | 与页面底色形成轻微层次 |
| `text.primary` | `#18232D` | 标题、正文、必填字段 | 对比度优先 |
| `text.secondary` | `#64717D` | 日期、辅助说明、更新时间 | 不承载关键状态 |
| `action.primary` | `#1F5E8C` | 主按钮、选中控件、链接 | 只强调可执行主路径 |
| `status.success` | `#2F7D4A` | 已恢复、已完成、权限已允许 | 同时显示文字和图标 |
| `status.attention` | `#B4691D` | 待跟进、临近到期、排班未确认 | 不做全屏警告 |
| `status.danger` | `#B3433A` | 作废、替换、保存失败、权限拒绝 | 高风险动作需二次确认 |
| `status.info` | `#356B83` | 应用内说明、自动保存提示 | 不与业务状态混用 |
| `border.default` | `#D8DEE4` | 分隔线、输入框边界 | 1dp |
| `focus.ring` | `#1F5E8C` | 键盘/无障碍焦点 | 2dp 外描边 |

状态颜色只作为第二信号。每个状态组件至少包含：状态图标、中文状态文字、必要时的补充结果或期限文字。

### 1.2 字体与层级

使用 Android 系统中文字体回退和 Material 3 `Typography`，不引入产品外字体。所有字距保持 `0sp`，不随屏幕宽度缩放字号。

| 层级 | 规格 | 示例 |
| --- | --- | --- |
| 页面标题 | 20sp，`SemiBold`，行高 28sp | “今日工作台” |
| 设备/记录主标题 | 18sp，`SemiBold`，行高 24sp | “1号雷达” |
| 区块标题 | 16sp，`SemiBold`，行高 22sp | “待跟进” |
| 正文和输入 | 16sp，`Regular`，行高 24sp | 故障现象、下一步动作 |
| 辅助信息 | 14sp，`Regular`，行高 20sp | “最近修改 18:24” |
| 状态标签 | 13-14sp，`SemiBold`，行高 20sp | “处理中” |
| 按钮文字 | 15sp，`SemiBold`，单行或可换行 | “确认替换本机数据” |

长文案必须换行；状态、设备名和高风险影响范围不得以省略号隐藏。

### 1.3 间距、尺寸与层级

- 基础间距为 8dp；页面水平内边距 16dp；相邻字段 12-16dp；区块之间 24dp。
- 可点击控件最小触控区域 48dp，图标本体建议 24dp。顶部返回、设置、更多等图标按钮统一 48dp 方形区域。
- 输入框、列表行、按钮使用稳定最小高度：单行输入 56dp，多行输入最小 104dp，主按钮 52dp，底部操作区 80dp（含安全区）。
- 圆角最大 8dp。列表和表单使用平面分组、分隔线和轻微背景差，不使用卡片嵌套卡片。
- 页面滚动区域与固定操作区分离；底部操作区使用 `surface.content` 和 1dp 顶部分隔线，不覆盖最后一条输入内容。

### 1.4 组件规范

| 组件 | 表现 | 使用场景 |
| --- | --- | --- |
| 顶部应用栏 | 返回 + 页面标题 + 可选更多/设置；高度 64dp | 所有内页 |
| 主入口按钮 | 2×2 等宽等高，图标在上、中文文案在下，最小 88dp 高 | 首页四入口 |
| 主按钮 | `action.primary` 填充，52dp，高风险不使用此样式 | 保存、确认主路径 |
| 次按钮 | 主色描边或 `surfaceVariant`，同样 52dp | 同一状态的次要动作 |
| 危险菜单项 | 文字和危险图标，菜单中不填充整行红色 | 作废、替换、清空 |
| 状态标签 | 图标 + 文字 + 结果/期限，圆角 6dp，背景为对应颜色 10% | 处理、交接、恢复结果 |
| 信息横幅 | 左侧图标，文字最多三行，支持动作链接 | 排班未确认、权限拒绝、保存失败 |
| 多行输入 | 标签、必填星号、输入区、错误/保存状态行 | 现场长文本 |
| 单选组 | Material 3 `RadioButton`，整行可点，文字始终可见 | 恢复结果、班组 |
| 分段切换 | `SegmentedButton`，固定宽度，选中同时有文字和勾选图标 | 自然日/本次出勤 |
| 底部固定操作区 | 两个等宽按钮或一个全宽按钮，随状态改变但位置不变 | 结束处理、交接详情 |
| 加载骨架 | 保留标题、字段和操作区轮廓；局部进度指示 | Flow 初次加载、备份校验 |

### 1.5 图标与无障碍

使用 Material 3/Material Icons 已有图标，不手绘 SVG。推荐语义映射：

| 语义 | 图标 | 必须配文字 |
| --- | --- | --- |
| 故障 | `ReportProblem` | 记录故障、故障状态 |
| 普通工作 | `Build` | 记录工作、工作来源 |
| 交接 | `AssignmentTurnedIn` | 写交接、交接状态 |
| 查找 | `Search` | 查找、搜索结果 |
| 返回/设置/更多 | `ArrowBack` / `Settings` / `MoreVert` | 由 `contentDescription` 描述 |
| 草稿 | `EditNote` | 草稿（尚未开始） |
| 处理中 | `Engineering` | 处理中 |
| 待验证 | `FactCheck` | 待验证 |
| 已结束 | `StopCircle` | 已结束 |
| 已取消 | `Cancel` | 已取消 |
| 已恢复/完成 | `CheckCircle` | 已恢复、已完成 |
| 未恢复/待跟进 | `FollowTheSigns` 或 `PendingActions` | 未恢复、待跟进 |
| 逾期 | `WarningAmber` | 逾期 N 天 |
| 作废 | `VisibilityOff` | 已作废 |
| 保存失败 | `ErrorOutline` | 保存失败 |
| 重试 | `Refresh` | 重试 |
| 导出/导入 | `FileUpload` / `FileDownload` | 导出备份、选择备份文件 |
| 筛选 | `FilterList` | 筛选 |

图标按钮的 `contentDescription` 必须描述动作，例如“打开设置”“打开更多操作”“打开筛选”；状态图标还必须有可读中文状态，不能只让 TalkBack 读颜色。

## 2. 响应式与现场可用性

### 2.1 目标尺寸

| 画布 | 结构 | 关键验收 |
| --- | --- | --- |
| 手机紧凑：360×800dp | 单列，16dp 边距；底部固定操作区 | 不横向滚动；最宽按钮文案可完整显示 |
| 手机常用：412×915dp | 单列，内容最大 680dp；长列表可滚动 | 首页四入口仍等宽；草稿区不挤压待跟进 |
| 大屏/桌面预览：1280×800dp | 内容最大 720dp 居中；列表页可左列表右详情，表单仍单列 | 不拉伸输入框到难读宽度；固定操作区与详情列对齐 |

### 2.2 断点规则

- `Compact`：顶部应用栏、主体、底部操作区单列；详情页底部按钮各占 1/2 宽度。
- `Medium/Expanded`：页面内容最大 720dp；列表与详情可采用 360dp/1fr 两列，但不增加新的业务入口；创建表单仍保持单列，右侧只放当前记录摘要。
- 首页在大屏上将“今日工作”和“待跟进”并列，其余“未完成草稿”“最近故障”位于下一行；四个主入口仍在首屏同一组内。
- 所有固定操作区使用 `WindowInsets.navigationBars` 和 `imePadding()`；键盘出现时操作区随内容上移或可滚动到，不遮挡最后一个字段。

### 2.3 字体放大、键盘与旋转

- 以系统字体 1.0、1.3、2.0 三档检查。字号放大时允许按钮文字换成两行，按钮高度不低于 56dp，底部区域不改成浮动覆盖。
- 多行输入获得焦点后，自动滚动至输入框下方留出至少 96dp；“确认结束”“保存”仍可通过滚动到固定底部区域触达。
- 设备旋转或进程重建后，从 ViewModel 状态和本地草稿恢复，不依赖页面临时变量。
- 窄屏下日期时间显示分两行，例如“2026-08-14”与“20:00-次日 08:00”，不缩小到难读。

## 3. 导航与交互基线

- 首页是唯一高频总入口；不使用底部导航栏。设置只从首页右上角 `Settings` 进入。
- 所有内页顶部左侧为返回；返回不弹“是否保存”阻塞确认，先触发一次自动保存，再返回。
- 表单页使用底部固定主操作区；页面滚动只影响字段区。自动保存状态放在标题下方或字段错误行，不占底部主按钮位置。
- 高风险动作“作废记录”“作废故障记录”“确认替换本机数据”使用二次确认对话框，确认文案说明保留关系、隐藏范围和不可直接恢复的影响。
- “取消本次处理”和“取消事项”是可见业务动作，显示为“已取消”；“作废”是隐藏动作，显示为“已作废”，两者永不互换。
- 现场输入采用先保存后补充：设备名称、故障现象、工作内容和交接下一步动作等必填项的错误要在字段下方即时显示；长文本写入失败保留内存内容并提供重试。

## 4. 页面一：首页今日工作台

### 4.1 手机高保真布局

```text
├──────────────┬─────────────────┤
│ 记录故障     │ 记录工作          │ 2×2 等宽入口
├──────────────┼─────────────────┤
│ 写交接       │ 查找              │
├────────────────────────────────┤
│ 今日工作                         │ 区块标题
│ 3 条记录                         │
│ 故障 · 更换控制柜保险丝   已结束 │ 记录行
│ 工作 · 完成三号线巡检     已完成 │
│                         查看 ›   │
├────────────────────────────────┤
│ 待跟进                           │
│ 2 条未完成 · 1 条已逾期           │
│ 逾期 1 天  1号雷达连接线确认      │ 图标+文字
│                         查看 ›   │
├────────────────────────────────┤
│ 未完成草稿（有草稿时显示）         │ 仅有 DRAFT 时出现

```

在 360dp 宽度下，日期与出勤摘要允许换成两行；四个入口仍保持 2×2、每格高度不小于 88dp。首页主体纵向滚动，顶部标题、出勤摘要和入口区域在滚动时保持可回到首屏，不把设置或备份等低频入口塞入工作区。

### 4.2 大屏布局

内容最大宽度 720dp 居中。四入口在顶部保持 2×2；其下使用两列：左列为“今日工作”和“最近故障”，右列为“待跟进”和条件显示的“未完成草稿”。右列不改变列表排序和数量，桌面只是并排展示。

### 4.3 主要状态

- 无记录：在对应区块显示“今天还没有工作记录”“当前出勤还没有工作记录”“当前没有待跟进事项”“还没有故障记录”，保留区块标题和下一步入口。
- 有 DRAFT：只显示未取消、未作废的 `DRAFT`；没有 DRAFT 时整个“未完成草稿”区块不渲染，不留空白占位。
- 排班未确认：日期/出勤下方显示信息横幅“本月排班尚未确认”“这不会阻止你记录工作”，动作文字为“去确认”。
- 通知被拒绝：待跟进区块仍显示应用内提醒，不以系统权限状态替代业务提醒。
- 跨午夜：本次出勤视图按 attendance 快照显示整段记录；自然日视图按 `workDate` 显示。派生记录的 `workDate` 显示出勤开始日。

### 4.4 操作与技术映射

| 控件/文案 | 呈现 | 技术映射 |
| --- | --- | --- |
| 设置图标 | 顶栏右侧 `Settings` | 仅导航到设置路由；技术稿未定义导航 UseCase |
| 自然日 / 本次出勤 | 二段式切换，选中带勾 | `HomeQueryUseCase.observe(HomeQuery)`；`HomeQuery` 的视图字段枚举需技术确认 |
| 修正 | 出勤摘要右侧文字按钮 | 读取 `AttendanceQueryUseCase.observeForDate(date)`；保存由 `AttendanceUseCase.update`/`setCurrent` |
| 记录故障 | 主入口按钮 | 仅导航；表单提交调用 `FaultUseCase.createDraft` |
| 记录工作 | 主入口按钮 | 仅导航；表单提交调用 `WorkLogUseCase.createManual` |
| 写交接 | 主入口按钮 | 仅导航；表单提交调用 `HandoverUseCase.create` |
| 查找 | 主入口按钮 | 仅导航；结果查询调用 `SearchUseCase.search` |
| 今日工作“查看” | 区块右侧文字按钮 | `WorkLogQueryUseCase.observeList(query)` |
| 待跟进“查看” | 区块右侧文字按钮 | `HandoverQueryUseCase.observeList(query)` |
| 草稿条目 | 整行可点 | `FaultQueryUseCase.observeDetail(faultId)`；由 `HomeUiState.draftList` 提供 ID |
| 最近故障条目 | 整行可点 | 详情读取 `FaultQueryUseCase.observeDetail(faultId)`；完整故障列表查询接口未在技术稿显式定义，见“接口缺口” |
| 去确认 | 信息横幅动作 | 导航到排班页；确认调用 `ShiftScheduleUseCase.confirmMonth` |

## 5. 页面二：快速记录故障

### 5.1 手机高保真布局

```text
┌────────────────────────────────┐
│ 返回  记录故障                  │
├────────────────────────────────┤
│ 设备名称 *                     │
│ [输入设备名称                 ×] │ 56dp 输入
│ 最近使用：1号雷达 · 3号线       │ 下拉建议，不跳页
│                                │
│ 接报时间                        │
│ [2026-08-14 10:26          ›]   │ 可编辑日期时间
│                                │
│ 故障现象 *                      │
│ ┌────────────────────────────┐ │
│ │ 信号强度偏弱                │ │
│ │                            │ │
│ └────────────────────────────┘ │ 最小 104dp
│ 自动保存：刚刚                 │ 非阻塞状态行
├────────────────────────────────┤
│          保存草稿              │ 固定底部主按钮
└────────────────────────────────┘
```

设备建议使用底部锚定下拉面板，最多显示最近使用和常用名称，不新建设备树。接报时间选择器在 360dp 上采用全宽底部表单，保存后回填一行；设备名和现象错误固定在各自字段下，不改变底部按钮位置。

### 5.2 大屏布局与键盘

大屏保持单列表单，宽度 600-640dp 居中，右侧不放营销说明。键盘弹出时故障现象输入区上移，底部按钮进入 IME 上方安全区；点击保存后先持久化，再导航到详情。

### 5.3 主要状态

- 初始：接报时间由注入的 `Clock` 生成，可修改；已有当前出勤时复用该出勤，不按日期重新创建普通班。
- 校验失败：设备名称或故障现象为空时，字段下显示“请填写设备名称”“请填写故障现象”，底部按钮保持可见但不提交。
- 保存中：按钮文字变为“正在保存草稿”，保留高度并禁用重复点击。
- 保存失败：显示“保存失败：空间不足/数据库异常/校验失败”，保留输入，按钮恢复为“重试保存草稿”。
- 离开页面：自动保存，不弹出“是否保存”对话框；若自动保存失败，返回前保留内存内容并在下一次打开时显示重试横幅。

### 5.4 操作与技术映射

| 控件/文案 | 呈现 | 技术映射 |
| --- | --- | --- |
| 返回 | `ArrowBack` 图标按钮 | 仅导航；离开前触发一次 `FaultUseCase.saveDraft`（已有草稿）或等待 `createDraft` 提交 |
| 设备名称输入 | 单行 `OutlinedTextField`，支持清除 | 建议来源 `DeviceUseCase.observe(includeInactive = false)`；写入作为 `CreateFaultDraftInput.deviceId/name`，具体字段名需技术确认 |
| 清除设备名称 | 输入框右侧 `Close` 图标 | 先清空当前内存值；已有草稿时调用 `FaultUseCase.saveDraft` 写入空值并由校验阻止提交 |

### 17.2 恢复流程四步视觉

恢复使用同一页面内的步骤指示器，步骤固定为：

1. 选择备份文件：通过系统 SAF 文件选择器，选中 `.coda-backup`。
2. 校验文件：显示局部进度和“正在校验备份文件”，不跳转空白页。
3. 数量预览：展示设备、别名、故障、处理记录、工作记录、交接事项、出勤、排班的数量；明确“将替换本机业务数据”。
4. 自动保护当前数据后确认：显示“当前数据已安全备份”，底部危险主按钮写“确认替换本机数据”。

用户取消、文件损坏、哈希不匹配、外键错误、安全备份失败或恢复中断时，本机业务数据保持不变。恢复成功后回到备份页，提示草稿仍可继续编辑、已作废记录默认隐藏。

### 17.3 恢复中断与 PREPARED

App 启动发现 restore journal 为 `PREPARED` 时，首先使用安全备份回滚。页面显示全屏但克制的异常状态：

```text
恢复未完成

本机数据已回滚到恢复前的安全备份，原有记录未被清除。

[查看备份与恢复]       [重新选择备份]
```

这里的“已回滚”是启动恢复流程的结果，不是新增业务状态。视觉稿不新增“恢复中断”数据库字段，也不提供独立回滚按钮；技术稿没有暴露 restore journal 查询/回滚 UseCase，见接口缺口。

## 18. 页面十五：空态、加载态与异常态

### 18.1 通用空态

空态沿用页面结构，不使用大插画或营销文案。图标 32dp、标题 16sp、说明 14sp、下一步按钮 48dp。

| 场景 | 主文案 | 下一步 | 技术映射 |
| --- | --- | --- | --- |
| 今日工作为空 | 今天还没有工作记录 | 记录工作 | 导航；创建调用 `WorkLogUseCase.createManual` |
| 本次出勤为空 | 当前出勤还没有工作记录 | 记录工作 | 同上；查询来自 `HomeQueryUseCase.observe` |
| 待跟进为空 | 当前没有待跟进事项 | 写交接 | 导航；创建调用 `HandoverUseCase.create` |
| 最近故障为空 | 还没有故障记录 | 记录故障 | 导航；创建调用 `FaultUseCase.createDraft` |
| 搜索为空 | 没有找到匹配记录 | 调整筛选 | `SearchUseCase.search` |
| 设备为空 | 还没有设备名称 | 添加设备 | `DeviceUseCase.create` |

### 18.2 局部加载态

列表加载时保留标题、区块和底部操作区，使用 3-5 行浅灰骨架；详情加载时保留设备名位置、状态行和字段轮廓。只读 Flow 错误不让整页闪白，错误横幅占据对应区块并保留其它区块。

| 场景 | 文案 | 操作 |
| --- | --- | --- |
| 首页聚合加载 | 正在加载今日工作 | 无；保持四入口可用 |
| 详情加载 | 正在加载记录 | 返回 |
| 保存处理中 | 正在保存 | 禁用当前提交按钮 |
| 备份校验 | 正在校验备份文件 | 取消；不替换本机数据 |
| 恢复写入 | 正在替换本机数据，请勿关闭应用 | 仅显示进度，不提供中途确认按钮 |

### 18.3 保存失败和权限拒绝

- `StorageFull`：横幅标题“保存失败：存储空间不足”，说明“输入内容仍保留在当前页面”，动作“重试”。
- `DatabaseFailure`：横幅标题“保存失败：本地数据库异常”，动作“重试”；不清空输入。
- `ValidationFailure`：字段下显示具体原因，底部主按钮恢复可用。
- `Conflict`：例如未结束处理作废，显示“当前处理尚未结束，不能作废。请先取消本次处理或结束本次处理。”，动作“返回处理记录”。不提供强制作废入口。
- `PermissionDenied`：通知页显示“系统通知权限未允许”，动作“打开系统设置”；首页继续显示应用内提醒。

### 18.4 恢复失败与中断

| 场景 | 视觉文案 | 保证 |
| --- | --- | --- |
| 文件格式错误 | 备份文件格式不受支持 | 本机数据不变；“重新选择备份文件” |
| 完整性校验失败 | 备份文件校验失败，文件可能已损坏 | 本机数据不变；“重试校验” |
| 外键/枚举错误 | 备份内容与当前版本不兼容 | 本机数据不变；不进入替换确认 |
| 安全备份失败 | 无法保护当前数据，暂不执行恢复 | 本机数据不变；“重试安全备份” |
| PREPARED 启动回滚 | 恢复未完成，已回滚到恢复前数据 | 自动使用安全备份；允许重新选择 |
| 恢复进程被杀 | 下次启动显示同一 PREPARED 回滚态 | 不区分事务此前是否提交 |

### 18.5 自动保存状态

标题下方使用非阻塞状态行：“正在保存”“已保存 18:24”“保存失败，点击重试”。状态行不作为业务状态，不改变 `DRAFT`、`IN_PROGRESS` 等枚举，也不替代底部按钮。

### 18.6 异常态按钮映射

| 异常态按钮 | 处理呈现 | 技术映射 |
| --- | --- | --- |
| 重试保存草稿 | 保留原输入、恢复提交按钮 | 重试 `FaultUseCase.createDraft` 或 `saveDraft` |
| 重试处理字段保存 | 保留原输入 | 重试 `FaultUseCase.updateProcessing` |
| 重试结束本次处理 | 保留恢复结果和下一步 | 重试 `FaultUseCase.finishProcessing` |
| 重试查找 | 保留关键词和筛选 | 重试 `SearchUseCase.search` |
| 重试加载详情 | 保留页面骨架 | 重试对应 `FaultQueryUseCase`/`WorkLogQueryUseCase`/`HandoverQueryUseCase` |
| 重试校验 | 保留已选文件 | 重试 `BackupUseCase.inspect` |
| 重试安全备份 | 不进入替换 | 由 `BackupUseCase.replace` 的前置安全备份流程重试；若实现需要独立调用，列为接口确认 |
| 打开系统设置 | 跳转 Android 应用通知设置 | `NotificationSettingsUseCase.openSystemSettings` |
| 返回处理记录 | 从冲突态回到未结束处理 | `FaultQueryUseCase.observeProcessing`；不绕过状态守卫 |
| 重新选择备份 | 回到 SAF 选择器 | 平台文件选择器后再次 `BackupUseCase.inspect` |
| 去确认排班 | 回到月度排班页 | `ShiftScheduleQueryUseCase.observeMonth`，提交时 `confirmMonth` |

## 19. 接口映射总表与待技术确认问题

### 19.1 已有契约的视觉绑定

| 视觉区域 | 读取契约 | 写入契约 |
| --- | --- | --- |
| 首页今日工作台、自然日/本次出勤、草稿区、最近故障、排班提醒 | `HomeQueryUseCase.observe(HomeQuery)` | `AttendanceUseCase.ensureDefaultForDate(today)`；各入口进入对应页面 |
| 快速故障、故障草稿 | `DeviceUseCase.observe(false)`、`FaultQueryUseCase.observeDetail` | `FaultUseCase.createDraft`、`saveDraft`、`cancelProcessing` |
| 故障处理中/待验证 | `FaultQueryUseCase.observeProcessing`、`observeDetail` | `startProcessing`、`updateProcessing`、`markPendingVerification`、`resumeProcessing`、`cancelProcessing` |
| 结束本次处理 | `FaultQueryUseCase.observeProcessing` | `FaultUseCase.finishProcessing`；消费 `FinishProcessingResult` |
| 故障终态/作废 | `FaultQueryUseCase.observeDetail`、对应工作/交接 Query | `voidFault`、`voidProcessing` |
| 普通工作列表/详情 | `WorkLogQueryUseCase.observeList`、`observeDetail` | `WorkLogUseCase.createManual`、`updateManual`、`void` |
| 交接列表/详情 | `HandoverQueryUseCase.observeList`、`observeDetail` | `HandoverUseCase.create`、`update`、`markHandedOver`、`markInProgress`、`complete`、`cancel`、`void` |
| 搜索与筛选 | `SearchUseCase.search(query, filters)` | 无业务写入；筛选只改变查询参数 |
| 当前出勤 | `AttendanceQueryUseCase.observeForDate` | `AttendanceUseCase.save`、`update`、`setCurrent`、`ensureDefaultForDate` |
| 月度排班 | `ShiftScheduleQueryUseCase.observeMonth` | `ShiftScheduleUseCase.confirmMonth`、`updateFutureSlot` |
| 设备名称与别名 | `DeviceUseCase.observe(includeInactive)` | `create`、`rename`、`addAlias`、`removeAlias`、`setActive` |
| 通知设置 | `NotificationSettingsUseCase.observe`、`permissionState` | `setEnabled`、`openSystemSettings` |
| 备份与恢复 | `BackupUseCase.inspect` 返回 `BackupPreview` | `export`、`replace` |

### 19.2 不自行发明接口的缺口

以下项目在视觉上有入口或状态呈现需要，但技术稿没有提供足够明确的契约。本稿只标记问题，不新增接口名称、字段或状态：

1. **导航路由不是领域 UseCase**：返回、首页四入口、设置、详情跳转均由技术稿提到的 Navigation Compose 路由承载，但没有显式路由表或参数契约。实现时需要确认路由参数（faultId、processingId、workLogId、handoverId、month），视觉稿不定义新的业务接口。
2. **首页“最近故障查看全部”**：技术稿有 `FaultQueryUseCase.observeDetail`，没有明确的故障列表查询接口。应确认是否由 `HomeQueryUseCase` 扩展查询范围或复用 `SearchUseCase`，不能在 UI 层自行添加 `observeList`。
3. **`HomeQuery` 视图切换字段**：技术稿只给出 `observe(query: HomeQuery)`，没有列出自然日/本次出勤的参数名和返回结构。需确认查询参数及空态字段，视觉上只保留两个既定模式。
4. **快速页自动保存输入结构**：`createDraft`、`saveDraft` 已存在；v1.1 已明确 DRAFT 详情不编辑设备名称，设备名在创建时写入关联和快照，后续 `FaultDraftPatch` 只承载故障现象、接报时间等既有草稿字段。设备建议使用 `DeviceUseCase.observe(false)`，不新增独立“关键词”字段。
5. **草稿取消**：技术稿明确 UI“取消草稿”映射 `cancelProcessing`，没有独立 `cancelDraft`。若实现希望拆分，需先更新技术契约；视觉稿继续使用现有映射。
6. **结束输入的下一步字段**：`FinishProcessingInput` 的完整字段未在技术稿展开。视觉只使用产品已定的验证结果、恢复结果、下一步动作和跟进期限，不新增恢复结果枚举。
7. **交接筛选 `includeVoided`**：`HandoverQueryUseCase.observeList(query)` 未明确是否包含 `includeVoided`。视觉要求默认隐藏、筛选后可见；需在现有查询参数中确认，不新增替代状态。
8. **设备编辑原子性**：设备名、别名、启停分别有 UseCase，但没有组合保存契约。实现需确认调用顺序和失败回滚，视觉不承诺一个未定义的 `updateDevice`。
9. **通知权限跳转的系统实现**：`openSystemSettings()` 已列在技术稿，但 Android Intent 目标和返回后的刷新时机未写明；视觉只显示“打开系统设置”。
10. **PREPARED 回滚状态读取**：技术稿规定启动看到 `PREPARED` 一律使用安全备份回滚，但没有 `observeRestoreJournal` 或 `rollback` UI 契约。视觉只定义启动异常态和自动回滚后的重试入口，不新增业务恢复状态。
11. **异常重试**：技术稿使用同一个命令型 UseCase 重试，没有独立 Retry UseCase。视觉所有“重试”都重新调用最近一次同一命令或查询，保留输入和原参数。
12. **关于 CODA**：UI 规格列出入口，但技术稿没有内容或查询契约。本稿不设计新业务字段；如保留入口，只显示静态版本/免责声明，需产品与技术确认是否进入 MVP。

## 20. 一致性检查

### 20.1 状态与作废

- [x] `DRAFT`、`IN_PROGRESS`、`PENDING_VERIFICATION`、`ENDED`、`CANCELED` 在标题、列表行、状态标签中都有独立文字和图标。
- [x] DRAFT 详情处理记录固定显示“草稿（尚未开始）”，不出现“暂无处理记录”。
- [x] `CANCELED` 是可见业务终态；`VOIDED`/`voidedAt` 只在更多菜单、筛选结果和只读详情中显示，不替代 `CANCELED`。
- [x] 未结束处理不能直接作废；故障存在未结束处理时不显示故障作废入口，并在冲突错误态解释原因。
- [x] `ENDED` 只表示本次处理结束；只有恢复结果为“已恢复”时才显示故障已恢复/关闭语义。

### 20.2 交接、出勤与跨午夜

- [x] 交接详情底部双主按钮严格按待交接、已交接、处理中渲染；已完成、已取消的底部主操作区只读，更多菜单作废仍按隐藏作废规则处理。
- [x] “继续处理故障”只在故障来源、故障可处理且位于更多菜单时显示；手动事项和普通工作来源隐藏。
- [x] 手动事项摘要为空显示“待跟进事项”。
- [x] 首日仅在本机没有任何当前出勤时自动创建普通班 08:00-18:00；有前一日开始且尚未结束的夜班时复用，不按新日期跳班。
- [x] 首页“自然日/本次出勤”为内联切换，就地刷新，不引入新页面或新业务视图。
- [x] 跨午夜派生工作记录的 `workDate` 和月底 00:00-08:00 片段按出勤/班次开始日归属；次日 08:00-20:00 按新月份排班。

### 20.3 通知、备份与设备

- [x] 通知只呈现非精确 AlarmManager/WorkManager 语义，文案为“提醒时间由系统自动安排”“不保证精确到分钟”，不展示精确闹钟权限。
- [x] 备份明确“不加密，请妥善保管”，恢复不会覆盖本机通知等偏好。
- [x] 看到 `PREPARED` 时视觉上先呈现安全备份回滚后的恢复中断态，不允许把半恢复数据当作成功。
- [x] 设备别名是“用户补充关键词”的承载位置，未新增独立关键词字段。
- [x] 停用设备只影响新建建议，不删除历史记录、关联关系或快照。

### 20.4 视觉范围与技术边界

- [x] 未新增照片、云同步、复杂统计、正式考勤、团队协作、附件、OCR、AI 诊断或在线冲突入口。
- [x] 视觉状态“加载中”“保存失败”“权限拒绝”“恢复中断”均为临时 UI 呈现，不新增领域枚举、数据库字段或业务终态。

## 21. 视觉验收清单

1. 首页首次进入能看到日期、当前出勤、四入口；没有当前出勤时只创建一次普通班 08:00-18:00。
2. 首页有 DRAFT 时显示“未完成草稿”区块，无 DRAFT 时完全隐藏；点击草稿直接进入故障详情。
3. 故障详情 DRAFT 显示“草稿（尚未开始）”；开始处理后状态改为“处理中”，不生成第二条首个处理记录。
4. 处理中和待验证字段自动保存；底部动作分别为“标记为待验证/结束本次处理”和“继续处理/结束本次处理”。
5. 结束处理五种恢复结果文字完整；非已恢复结果必须出现下一步动作和跟进期限，并显示组合状态。
6. 同一次结束重复点击不会出现第二条工作记录或第二条自动交接事项。
7. 交接详情双按钮按状态固定；“继续处理故障”不占底部按钮并只对故障来源出现。
8. 搜索“信号弱”能展示包含“信号强度偏弱”的故障处理结果；默认作废隐藏，筛选后显示“已作废”。
9. 当前出勤页能表达普通班、顶白班、顶夜班、自定义和同日多段；顶夜班显示跨午夜完整日期时间。
10. 月排班未确认时仍可记录工作，页面不猜测甲/乙班；未来修正不改变历史快照。
11. 通知拒绝时首页应用内提醒仍存在；设置页不出现精确闹钟权限。
12. 备份导出提示未加密；恢复预览显示数量，安全备份完成后才显示“确认替换本机数据”；`PREPARED` 启动态先回滚。
13. 存储不足、数据库异常、校验失败、权限拒绝、冲突和恢复中断均保留原输入/原数据，并提供对应的现有 UseCase 重试或返回动作。
