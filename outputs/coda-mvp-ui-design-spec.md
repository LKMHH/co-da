# CODA｜现场工作助手 MVP UI 设计规格

> 文档状态：v1.1（冻结修订）
> 产品基线（v1.0，不修改）：`outputs/electrician-workbench-mvp-product-design.md`
> 技术基线（v1.1.1）：`outputs/coda-mvp-technical-design-draft.md`
> 视觉稿（v1.1）：`outputs/coda-mvp-visual-design-spec.md`
> 设计目标：把已确认的产品流程转换成可评审、可实现的 Android UI 规格。

## 1. 设计定位

### 1.1 v1.1 冻结裁决

- 交接详情中的“已完成”“已取消”只读，具体指底部固定主操作区不再提供业务状态转换按钮；既有更多菜单中的“作废记录”仍保留，作废只写入 `voidedAt` 并从默认列表隐藏，不改变原业务状态。
- DRAFT 故障详情不提供设备名称编辑入口。设备名称在快速记录创建时必填并形成关联快照；DRAFT 详情只编辑故障现象和接报时间。`FaultDraftPatch` 未明确支持设备字段，因此不在 UI 层扩展该行为。

CODA 是个人电工现场记录工具，不是宣传页、报表系统或正式考勤系统。UI 优先保证：

- 打开后能马上开始记录；
- 单手操作，现场输入量小；
- 状态清楚，不能把“处理结束”误解成“设备已恢复”；
- 长文本可以离开现场后补充；
- 空状态、逾期、权限拒绝和保存失败都有明确反馈；
- 页面结构稳定，内容变化不会让主要按钮跳动。

首版采用浅色主题、单一主导航首页和顶部设置入口，不使用底部导航，不在首页放低频管理功能。

## 2. 信息架构与导航

```text
首页 今日工作台
  ├─ 记录故障 -> 快速记录故障 -> 故障详情 -> 处理记录
  ├─ 记录工作 -> 普通工作记录 -> 工作详情
  ├─ 写交接   -> 交接事项 -> 继续处理故障/完成事项
  ├─ 查找     -> 搜索结果 -> 对应详情
  └─ 设置 ⚙
       ├─ 出勤与排班
       ├─ 通知设置
       ├─ 备份与恢复
       ├─ 设备名称与别名
       └─ 关于 CODA
```

四个主要入口使用等尺寸 2×2 田字布局。设置使用顶部右侧齿轮图标，不占用四个主入口。所有页面顶部保留返回按钮；表单页面底部保留固定主操作区。

## 3. 视觉设计系统

### 3.1 颜色

| 语义 | 颜色 | 用途 |
| --- | --- | --- |
| 页面背景 | `#F6F7F9` | 页面底色 |
| 内容背景 | `#FFFFFF` | 表单和列表区域 |
| 主文字 | `#18232D` | 标题、正文 |
| 次要文字 | `#64717D` | 日期、辅助说明 |
| 主操作 | `#1F5E8C` | 主按钮、选中状态 |
| 已恢复/已完成 | `#2F7D4A` | 成功状态 |
| 待跟进/临近到期 | `#B4691D` | 提醒状态 |
| 作废/替换 | `#B3433A` | 高风险操作 |
| 分隔线 | `#D8DEE4` | 列表和区块边界 |

状态必须同时显示文字和图标，不能只依赖颜色。蓝色只用于主操作，不让整个页面变成单一蓝色主题。

### 3.2 文字、间距和触控

- 页面标题：20sp，半粗；
- 区块标题：16sp，半粗；
- 正文和输入内容：16sp；
- 辅助信息：14sp；
- 状态标签：13-14sp；
- 触控目标高度至少 48dp；
- 页面水平内边距 16dp；
- 主要区块间距 24dp，相关字段间距 12-16dp；
- 使用 8dp 间距体系；
- 圆角不超过 8dp；
- 表单输入、列表行和按钮使用稳定高度，避免动态内容改变布局。

### 3.3 图标和按钮

主入口使用图标加文字：故障、工作、交接、搜索分别使用容易理解的图标。设置、返回、筛选、导出、导入等使用标准图标并提供无障碍描述。

按钮只承载明确动作。删除、作废和替换恢复使用警示色，并必须二次确认。普通“保存”“应用筛选”等动作使用主色，不使用危险色。

## 4. 首页：今日工作台

### 4.1 默认状态

```text
┌─────────────────────────┐
│ 今日工作台          ⚙    │
│ 2026-08-14 · 普通班       │
│ 今日工作 [自然日] [本次出勤]│
│ 当前出勤：普通班 08:00-18:00│
│                  修正 ›   │
├───────────┬─────────────┤
│ 记录故障   │ 记录工作     │
├───────────┼─────────────┤
│ 写交接     │ 查找         │
├─────────────────────────┤
│ 今日工作                 │
│ 3 条记录            查看 ›│
│ · 完成三号线巡检          │
│ · 更换控制柜保险丝        │
├─────────────────────────┤
│ 待跟进                   │
│ 2 条未完成 · 1 条已逾期   │
│ · 1号雷达连接线确认       │
│                     查看 ›│
├─────────────────────────┤
│ 未完成草稿（有草稿时显示） │
│ · 1号雷达 · 草稿     查看 ›│
├─────────────────────────┤
│ 最近故障                 │
│ · 1号雷达 · 已恢复        │
│ · 3号线 · 待验证          │
│                     查看 ›│
└─────────────────────────┘
```

设计规则：

- 日期、当前出勤和设置放在顶部；
- 四个入口等宽等高，不设置主次；
- “自然日/本次出勤”是首页今日工作列表的内联视图切换，默认选中自然日；切换后列表区、数量和空态就地刷新，不跳转新页面；
- 当前出勤摘要可点击进入出勤修正页；修正只影响后续记录，不改写已有工作记录的出勤快照；
- 本机没有任何当前出勤时才自动创建并设为当前的普通班 08:00-18:00；已有当前出勤（包括前一日开始且尚未结束的夜班）时直接复用，首页和记录工作页都显示该当前出勤；
- 内容顺序为今日工作、待跟进、未完成草稿（有草稿时）、最近故障；
- “未完成草稿”区块只在存在未取消、未作废的 DRAFT 时显示，点击条目直达对应故障详情；没有草稿时不留空白区块；
- 每个摘要区域最多显示 2-3 条，点击“查看”进入完整列表；
- 不放备份、设备管理、通知明细和统计图表；
- 页面纵向滚动，顶部入口保持可见。

### 4.2 首页状态

空状态只提示，不重复主入口：

```text
今日工作
今天还没有工作记录

本次出勤
当前出勤还没有工作记录

待跟进
当前没有待跟进事项

最近故障
还没有故障记录
```

逾期事项在待跟进区域第一条显示图标、文字和逾期天数，不使用全屏红色警告。排班未确认提示放在日期/出勤下方，显示“这不会阻止你记录工作”和“去确认”入口。

### 4.3 本次出勤视图

首页内联切换到“本次出勤”后，列表区就地刷新，只显示当前出勤快照关联的工作记录和派生工作记录，不跳转新页面；交接事项继续由“待跟进”区域按事项状态展示，不把没有出勤归属的手动事项错误归入本次出勤。跨午夜派生记录的 `workDate` 归出勤开始日；自然日视图按 `workDate` 显示，月底跨月的 00:00-08:00 片段仍按上一班次开始日归属，次日 08:00-20:00 按新月份排班处理。当前出勤摘要提供“修正出勤”入口，空态文案为“当前出勤还没有工作记录”。切回“自然日”后按 `workDate` 显示，不改变任何记录。

## 5. 快速记录故障

进入路径：`首页 -> 记录故障`。首屏只建档，不展示完整处理过程。

```text
┌─────────────────────────┐
│ ← 记录故障               │
├─────────────────────────┤
│ 设备名称 *              │
│ [输入设备名称        ×]  │
│ 最近使用：1号雷达 · 3号线 │
├─────────────────────────┤
│ 接报时间                │
│ 2026-08-14 10:26    ›   │
├─────────────────────────┤
│ 故障现象 *              │
│ ┌─────────────────────┐ │
│ │                     │ │
│ │                     │ │
│ └─────────────────────┘ │
├─────────────────────────┤
│         保存草稿         │
└─────────────────────────┘
```

- 设备名称和故障现象必填；
- 接报时间自动生成并允许修改；
- 最近设备以下拉建议显示，不跳转到新页面；
- 离开页面自动保存，不弹出阻塞式确认；
- 不要求现场填写原因、措施、验证或添加附件；
- 保存后进入故障详情，而不是直接回首页。
- 从首页进入到草稿完成持久化的人工验收目标不超过 60 秒。

## 6. 故障详情与处理

### 6.1 草稿

```text
┌─────────────────────────┐
│ ← 故障详情          ⋮    │
├─────────────────────────┤
│ 1号雷达                 │
│ 草稿 · 接报 10:26        │
├─────────────────────────┤
│ 故障现象                │
│ 信号强度偏弱             │
├─────────────────────────┤
│ 处理记录                │
│ 草稿处理（尚未开始）      │
├─────────────────────────┤
│         开始处理         │
└─────────────────────────┘
```

保存草稿时已经存在一条 `DRAFT` 处理占位。该占位只表示草稿闭环，不计入产品口径的实际处理次数，不生成工作记录或交接事项；开始处理后才进入实际处理记录。

接报时间显示在标题下方的紧凑信息行，完整日期和编辑入口点击后展开。

### 6.2 处理中

```text
┌─────────────────────────┐
│ ← 1号雷达          ⋮    │
│ 处理中 · 接报 10:26      │
│ 开始 10:42               │
├─────────────────────────┤
│ 检查结果                │
│ ┌─────────────────────┐ │
│ │                     │ │
│ └─────────────────────┘ │
├─────────────────────────┤
│ 初步判断                │
│ ┌─────────────────────┐ │
│ │                     │ │
│ └─────────────────────┘ │
├─────────────────────────┤
│ 最终原因                │
│ ┌─────────────────────┐ │
│ │                     │ │
│ └─────────────────────┘ │
├─────────────────────────┤
│ 处理措施                │
│ ┌─────────────────────┐ │
│ │                     │ │
│ └─────────────────────┘ │
├─────────────────────────┤
│ ┌───────────┬───────────┐ │
│ │ 标记为待验证│ 结束本次处理│ │
│ └───────────┴───────────┘ │
└─────────────────────────┘
```

输入内容自动保存，最终原因可以在现场离开后补充。页面只显示当前状态允许的动作：

- 草稿：开始处理；
- 处理中：标记为待验证、结束本次处理；
- 待验证：继续处理、结束本次处理；
- 已结束：查看结果和派生工作记录；
- 已取消：只读查看。

在“处理中”或“待验证”状态的 `⋮` 菜单中提供“取消本次处理”。确认后保留已填写内容，处理进度改为“已取消”，不生成派生工作记录，也不回推故障恢复状态；这与隐藏历史记录的“作废记录”是两个不同动作。

### 6.3 结束本次处理

结束动作打开确认区域，要求填写恢复结果；验证结果可以现场填写，也可以离开现场后补充：

```text
┌─────────────────────────┐
│ 结束本次处理             │
├─────────────────────────┤
│ 验证结果（可选）         │
│ ┌─────────────────────┐ │
│ │                     │ │
│ └─────────────────────┘ │
├─────────────────────────┤
│ 恢复结果 *              │
│ ○ 已恢复                │
│ ○ 临时恢复              │
│ ○ 部分恢复              │
│ ○ 未恢复                │
│ ○ 无法确认              │
├─────────────────────────┤
│          取消   确认结束 │
└─────────────────────────┘
```

选择临时恢复、部分恢复、未恢复或无法确认时，继续要求下一步动作和跟进期限，然后一次性生成工作记录、必要的交接事项并更新故障状态。

点击“确认结束”后立即禁用重复提交；重复触发只返回同一处理结果和同一条派生工作记录，不新增记录。

### 6.4 详情页更多操作

故障详情、处理记录详情、普通工作详情和交接详情的标题栏右侧统一提供 `⋮` 更多菜单。菜单至少包含“作废记录”（草稿只显示“取消草稿”；处理中/待验证的处理记录只显示“取消本次处理”）。`DRAFT`、`IN_PROGRESS`、`PENDING_VERIFICATION` 等未结束处理不能直接作废，必须先取消或结束；故障主记录存在未结束处理时也不能直接作废。只有 `ENDED` 或 `CANCELED` 的处理记录才显示“作废记录”。作废点击后弹出二次确认：作废故障主记录会将其显示为“已作废”；作废处理、工作或交接记录只增加作废标记并从默认列表隐藏，不物理删除、不改写其他故障状态或历史快照。已作废记录可在搜索筛选中选择“包含已作废”后查看，详情页显示“已作废”状态且只读。

## 7. 普通工作记录

进入路径：`首页 -> 记录工作`。普通工作不要求先创建故障。

```text
┌─────────────────────────┐
│ ← 记录工作               │
├─────────────────────────┤
│ 2026-08-14 · 普通班      │
├─────────────────────────┤
│ 工作内容 *              │
│ ┌─────────────────────┐ │
│ │                     │ │
│ │                     │ │
│ └─────────────────────┘ │
├─────────────────────────┤
│ 补充信息             ›   │
├─────────────────────────┤
│         保存工作记录     │
└─────────────────────────┘
```

“补充信息”展开后显示工作结果、设备、区域和安排来源。日期和出勤自动带入，普通记录可继续编辑。

### 7.1 普通工作详情与编辑

保存普通工作记录后进入工作详情页，而不是直接回首页：

```text
┌─────────────────────────┐
│ ← 工作详情          ⋮    │
├─────────────────────────┤
│ 完成三号线巡检           │
│ 2026-08-14 · 普通班      │
│ 最近修改 18:24           │
├─────────────────────────┤
│ 工作结果             ›   │
│ 出勤标记（可修正）   ›   │
│ 设备 / 区域 / 安排来源 › │
├─────────────────────────┤
│          编辑工作记录    │
└─────────────────────────┘
```

“编辑工作记录”允许修改工作内容、工作日期、出勤标记、工作结果、设备、区域和安排来源；保存后更新最近修改时间。出勤标记修正只影响这一条普通工作记录的快照，不改变当前出勤，也不改写其他历史记录。普通工作详情的 `⋮` 菜单提供“作废记录”。故障派生工作记录只读，详情页显示“返回对应处理记录修改”，不提供独立编辑按钮。

## 8. 交接与待跟进

进入路径：`首页 -> 写交接`，或从未恢复类故障处理自动进入。

```text
┌─────────────────────────┐
│ ← 写交接                │
├─────────────────────────┤
│ 事项摘要（可选）         │
│ ┌─────────────────────┐ │
│ │ 1号雷达信号偏弱      │ │
│ └─────────────────────┘ │
├─────────────────────────┤
│ 下一步动作 *             │
│ ┌─────────────────────┐ │
│ │ 待现场确认连接线      │ │
│ └─────────────────────┘ │
├─────────────────────────┤
│ 跟进期限 *               │
│ [下一班前] [今日下班前]  │
│ [指定时间] [暂无期限]    │
├─────────────────────────┤
│ 交给班组                │
│ [甲班] [乙班] [不指定]   │
├─────────────────────────┤
│ 可能隐患（可选）         │
│ ┌─────────────────────┐ │
│ │                     │ │
│ └─────────────────────┘ │
├─────────────────────────┤
│ 来源：故障 · 1号雷达     │
├─────────────────────────┤
│         保存交接事项     │
└─────────────────────────┘
```

事项摘要不是手动交接的必填字段。来源为故障或工作记录时自动带入摘要；手动事项未填写时保存为“待跟进事项”，保证列表始终有可识别标题。

交接详情底部动作按当前状态和来源渲染。以下仅示意“来源为故障、状态为处理中”时的按钮：

```text
┌─────────────────────────┐
│ ┌─────────────┬─────────┐ │
│ │    已完成    │ 取消事项 │ │
│ └─────────────┴─────────┘ │
└─────────────────────────┘
```

按钮同宽同高；底部固定两个主按钮。“继续处理故障”不占底部主按钮位置，统一放在 `⋮` 更多菜单中，仅当来源为故障处理且关联故障仍可处理时显示；手动事项或来源为普通工作记录时隐藏。继续处理会创建同一故障的新处理记录，但不自动把交接事项改成“处理中”；需要用户明确点击“标记处理中”。“已完成”只结束交接事项，不自动把故障改成已恢复。

“已交接”只表示已经通过口头、微信或纸质方式完成告知，不表示故障已经解决。

底部固定两个主操作：待交接显示“标记已交接”和“取消事项”，已交接显示“标记处理中”和“取消事项”，处理中显示“已完成”和“取消事项”；已完成、已取消的底部主操作区只读，不再提供状态转换按钮。既有更多菜单中的“作废”仍按来源/状态规则显示，作废只写入 `voidedAt` 并隐藏记录，不改变原业务状态。

交接详情必须显示当前状态文字和图标，并按状态提供操作：

| 状态 | 可用操作 | 说明 |
| --- | --- | --- |
| 待交接 | 标记已交接、继续处理故障（仅故障来源）、取消事项、作废 | 标记已交接只记录告知动作 |
| 已交接 | 继续处理故障（仅故障来源）、标记处理中、取消事项、作废 | 不改变故障恢复状态 |
| 处理中 | 继续处理故障（仅故障来源）、标记已完成、取消事项、作废 | “已完成”只结束交接事项 |
| 已完成 | 查看、作废 | 只读业务内容，不回推故障状态 |
| 已取消 | 查看 | 只读，保留关联 ID |

“标记处理中”“标记已完成”和“取消事项”均使用确认对话框；“取消事项”将状态改为可见的“已取消”，不改变关联故障状态。“作废”单独使用危险确认，只增加作废标记并从默认列表隐藏，不删除记录、不回推故障状态。状态按钮不得只用颜色区分，必须同时显示文字和图标。

### 8.1 待跟进列表

首页“待跟进”区域点击“查看”进入完整列表页，按“未完成 / 即将到期 / 已逾期”分组；列表底部提供“已完成”和“已取消”分组，也可通过状态筛选查看。已完成和已取消事项默认不在首页分组中。

```text
┌─────────────────────────┐
│ ← 待跟进事项        ⚲    │
├─────────────────────────┤
│ 未完成（2）              │

│   下一步：现场确认 · 下一班前 │
│ · 更换控制柜保险丝        │
│   下一步：领取备件 · 暂无期限 │
├─────────────────────────┤
│ 即将到期（1）            │
│ · 3号线复测              │
│   今天下班前              │
├─────────────────────────┤
│ 已逾期（1）              │
│ · 2号泵信号复核 · 逾期1天 │
└─────────────────────────┘
```

点击事项进入交接详情；列表显示状态文字、下一步动作、期限和来源，不只使用颜色区分。作废事项只有在筛选中打开“包含已作废”后显示；作废不会把状态文案改成“已取消”。

## 11. 出勤与排班

### 11.1 当前出勤

当前出勤是日常操作，和本月排班分开：

```text
┌─────────────────────────┐
│ ← 当前出勤               │
├─────────────────────────┤
│ 2026-08-14              │
│ 当前：普通班 08:00-18:00 │
├─────────────────────────┤
│ [普通班] [顶白班]        │
│ [顶夜班] [自定义]        │
├─────────────────────────┤
│ 时间 [08:00] 至 [18:00]  │
├─────────────────────────┤
│         保存出勤修正     │
└─────────────────────────┘
```

只有选择顶白班或顶夜班时才显示甲班/乙班选择。顶夜班明确展示跨午夜的完整日期时间。同一天存在多段出勤时，在当前出勤下方显示列表并使用添加按钮。

从首页“当前出勤”摘要或设置进入本页时，页面标题显示“修正当前出勤”。用户可以修改班次类型、起止时间和班组，再点击“保存出勤修正”；首次没有当前出勤时保存的出勤自动成为当前，已有当前出勤时只有明确选择/修正当前出勤才切换，修正不会改写已经保存的工作记录快照。若当天已有多段出勤，先选择要修正的出勤，再进入同一表单。

若本机还没有任何当前出勤，首次打开首页或保存第一条工作/故障记录时，自动创建并设为当前的普通班 08:00-18:00 出勤；若已有前一日开始且尚未结束的跨午夜出勤，则继续复用该出勤，不按新日期自动创建或切换普通班。用户仍可随后明确修正或新增其他出勤时段。

### 11.2 本月排班

```text
┌─────────────────────────┐
│ ← 本月排班 · 2026年8月    │
├─────────────────────────┤
│ 白班起点                │
│ ○ 甲班    ○ 乙班         │
│ 尚未确认                │
├─────────────────────────┤
│ 班次建议                │
│ 08-01 · 甲班白班     ›   │
│ 08-15 · 乙班白班     ›   │
│ 08-31 · 转班         ›   │
└─────────────────────────┘
```

排班修改只影响未来班次，已经保存的工作记录保留当时的出勤和班次快照。它不是正式考勤页面。

未确认白班起点时仍可记录工作，系统不猜测甲/乙班；月底跨月时，00:00-08:00 片段按上一班次开始日归属，次日 08:00-20:00 按新月份排班处理。

```text
┌─────────────────────────┐
│ ← 备份与恢复             │
├─────────────────────────┤
│ 导出当前数据             │
│ 将故障、工作、交接和排班  │
│ 保存为备份文件            │
│ 文件未加密，请妥善保管    │
│         导出备份         │
├─────────────────────────┤
│ 恢复本机数据             │
│ 导入备份会替换本机业务数据│
│ 手机通知等设置不会改变    │
│       选择备份文件       │
└─────────────────────────┘
```

导出是普通操作，直接打开系统文件保存窗口。备份文件包含故障、工作、交接、出勤、排班、设备名称及别名，并保留未完成草稿和已作废记录；数量预览要包含这些记录类别。首版不加密；导出成功后再次显示“文件未加密，请妥善保管”，不得暗示备份文件具备密码保护。恢复流程必须依次展示：选择文件、校验、记录数量预览、自动保护当前数据、确认替换。最终按钮明确写“确认替换本机数据”，不使用模糊的“导入”。首版不做合并恢复；恢复后草稿仍可继续编辑，已作废记录默认隐藏但可在筛选中查看。

## 14. 通用状态与交互

### 14.1 保存与草稿

- 故障和长文本输入自动保存；
- 离开页面不弹阻塞式确认；
- 保存失败时保留内存内容，显示具体错误和重试入口；
- 详情页显示最近保存状态，但不让自动保存提示占据主操作区域。
- App 重启后从首页的“未完成草稿”入口恢复最近草稿，进入故障详情继续编辑；草稿加载失败时保留本地草稿并显示重试入口。

### 14.2 错误、加载和空态

- 加载时保留页面结构，用局部加载指示器，不让整页闪烁；
- 没有数据时显示解释和下一步动作；
- 数据库、备份校验和权限失败均显示具体原因；
- 网络不可用不作为阻塞错误，因为首版不依赖网络。

### 14.3 高风险操作

作废、替换恢复和清空类操作必须二次确认，确认文案说明影响范围。取消、失败或系统中断后，页面回到安全状态，原数据不被隐藏式删除。

### 14.4 无障碍与可用性

- 图标按钮提供内容描述；
- 状态颜色同时配合文字和图标；
- 触控目标至少 48dp；
- 文本过长时换行，不用截断隐藏关键状态；
- 页面支持系统字体放大，关键按钮不因字体变化消失；
- 键盘弹出时，输入框和底部按钮保持可见或可滚动到。

## 15. 评审顺序

建议按以下顺序确认视觉稿：

1. 首页和快速故障；
2. 故障详情和结束处理；
3. 交接和普通工作；
4. 搜索及筛选面板；
5. 设置、出勤排班和通知；
6. 备份恢复和异常状态；
7. 颜色、字体、图标和 Compose 组件细节。

本稿采用的是已确认的推荐方案：主流程优先、设置低频化、表单最小化、状态显式化、危险操作可撤回。后续视觉稿只调整表现，不改变这些业务入口和状态含义。

开工后补强（P2，不阻塞 v1.1）：补充未结束处理作废守卫的端到端错误态、设备别名承载关键词与 `deviceAliases` 数量的真机回归，以及月底跨月两个时间片段的视觉验收。
