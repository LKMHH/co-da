# CODA UI 规格 v1.0 审阅摘要

来源：`C:\Users\74526\Documents\Codex\2026-08-14\019ffec2-1c7b-7791-8548-df2d59cfe1f3-2\outputs\coda-mvp-ui-design-spec.md`（UTF-8，完整读取；约 643 行）。以下只总结，不修改原 UI 规格。

## 全局视觉规范

- 定位：个人现场电工记录工具；浅色、实用、单手操作；不使用底部导航，首页为单一主导航，设置从右上角齿轮进入。
- 颜色：页面背景 `#F6F7F9`；内容背景 `#FFFFFF`；主文字 `#18232D`；次要文字 `#64717D`；主操作/选中 `#1F5E8C`；已恢复/已完成 `#2F7D4A`；待跟进/临近到期 `#B4691D`；作废/替换 `#B3433A`；分隔线 `#D8DEE4`。状态必须文字+图标，不能只靠颜色。
- 排版：页面标题 20sp 半粗；区块标题 16sp 半粗；正文/输入 16sp；辅助 14sp；状态 13-14sp。8dp 间距体系，页面水平内边距 16dp，主要区块 24dp、相关字段 12-16dp，圆角最多 8dp，触控目标至少 48dp。表单/列表/按钮保持稳定高度。
- 图标/按钮：入口图标+文字（故障、工作、交接、搜索）；设置/返回/筛选/导入导出用标准图标并提供无障碍描述。保存、应用筛选用主色；删除/作废/替换恢复用警示色并二次确认。

## 信息架构

首页今日工作台 -> 记录故障 -> 快速记录故障 -> 故障详情 -> 处理记录；记录工作 -> 普通工作记录 -> 工作详情；写交接 -> 交接事项 -> 继续处理故障/完成事项；查找 -> 搜索结果 -> 对应详情；设置 -> 出勤与排班、通知设置、备份与恢复、设备名称与别名、关于 CODA。首页四个主入口为等尺寸 2x2 田字布局；所有页顶有返回；表单页底有固定主操作区。

## 逐页结构、状态和可见文案

### 1. 首页“今日工作台”

- 顶部：标题“今日工作台”、齿轮；日期“2026-08-14 · 普通班”；内联切换“今日工作 [自然日] [本次出勤]”；当前出勤摘要“当前出勤：普通班 08:00-18:00”；入口“修正 ›”。
- 四入口：记录故障、记录工作、写交接、查找，等宽等高，无主次。
- 区块顺序：今日工作（最多 2-3 条，`查看 ›`）、待跟进（未完成/逾期摘要）、未完成草稿（仅有草稿时显示）、最近故障（最多 2-3 条）。不放备份、设备管理、通知明细、统计图表。
- 空态精确文案：`今天还没有工作记录`；`当前出勤还没有工作记录`；`当前没有待跟进事项`；`还没有故障记录`。逾期项首条需图标+文字+逾期天数，不全屏红色。
- 排班未确认提示：`这不会阻止你记录工作` + `去确认`。
- 关键规则：自然日/本次出勤是列表内联切换，就地刷新列表/数量/空态；本次出勤只显示当前出勤快照关联记录/派生记录，手动无出勤归属交接不能误归入；跨午夜派生 `workDate` 归出勤开始日。没有任何当前出勤才自动建普通班 08:00-18:00；已有当前出勤（含前日开始未结束夜班）复用。
- 草稿区标题“未完成草稿”，条目示例“1号雷达 · 草稿”；只返回未取消、未作废的 DRAFT，点击直达故障详情；无草稿不留空区。

### 2. 快速记录故障

- 顶栏“← 记录故障”。字段：`设备名称 *`（输入+清除，最近使用下拉“最近使用：1号雷达 · 3号线”）；`接报时间`（自动生成，可编辑，示例“2026-08-14 10:26 ›”）；`故障现象 *`多行输入；底部固定“保存草稿”。
- 设备名称、故障现象必填；不要求现场填写原因/措施/验证/附件；离开自动保存，不阻塞确认；保存后进入故障详情，不回首页；从首页到草稿持久化验收目标 <=60 秒。

### 3. 故障详情 DRAFT

- 顶栏“← 故障详情 ⋮”。标题“1号雷达”；紧凑状态行“草稿 · 接报 10:26”（点接报时间可展开完整日期/编辑）；区块“故障现象 / 信号强度偏弱”；“处理记录”必须显示占位 `草稿处理（尚未开始）`；底部主按钮“开始处理”。
- 保存草稿时已有一条 DRAFT 处理占位，仅表示草稿闭环，不计实际处理次数、不生成工作记录或交接；开始处理后才是实际处理记录。更多菜单对草稿为“取消草稿”，不能“作废记录”。

### 4. 故障详情 IN_PROGRESS / PENDING_VERIFICATION

- 顶栏示例“← 1号雷达 ⋮”，状态信息“处理中 · 接报 10:26”“开始 10:42”。固定字段多行自动保存：检查结果、初步判断、最终原因、处理措施。
- IN_PROGRESS 操作：`标记为待验证`、`结束本次处理`；菜单含“取消本次处理”。PENDING_VERIFICATION：`继续处理`、`结束本次处理`；菜单含“取消本次处理”。ENDED：查看结果和派生工作记录；CANCELED：只读。
- 取消处理需确认，保留已填内容，进度改“已取消”，不生成派生工作记录、不回推故障恢复状态；区别于隐藏历史“作废记录”。未结束 DRAFT/IN_PROGRESS/PENDING_VERIFICATION 不得直接作废；故障有未结束处理时也不得作废；仅 ENDED/CANCELED 处理可显示“作废记录”。作废只写标记并默认隐藏，不物理删除/改历史快照；搜索“包含已作废”才显示，详情显示“已作废”且只读。

### 5. 结束本次处理

- 确认区域标题“结束本次处理”；可选多行“验证结果”；必选单选“恢复结果 *”：`已恢复`、`临时恢复`、`部分恢复`、`未恢复`、`无法确认`；底部“取消”“确认结束”。
- 除“已恢复”外的四类结果继续要求下一步动作和跟进期限，然后一次生成工作记录、必要交接事项并更新故障状态。确认后禁用重复提交；重复触发返回同一结果/同一派生工作记录，不新增。

### 6. 普通工作记录与详情

- 新建顶栏“← 记录工作”；自动带入“2026-08-14 · 普通班”；必填多行“工作内容 *”；可展开“补充信息 ›”（工作结果、设备、区域、安排来源）；固定“保存工作记录”。保存后进入工作详情。
- 详情顶栏“← 工作详情 ⋮”；标题“完成三号线巡检”；日期/班次；“最近修改 18:24”；行项“工作结果 ›”“出勤标记（可修正） ›”“设备 / 区域 / 安排来源 ›”；底部“编辑工作记录”。允许改工作内容、工作日期、出勤标记、结果、设备、区域、安排来源；保存更新时间；出勤修正只影响此条快照。普通工作菜单“作废记录”。FAULT_DERIVED 只读，显示“返回对应处理记录修改”，无独立编辑。

### 7. 交接事项新建、列表、详情

- 新建顶栏“← 写交接”；字段：可选“事项摘要”（示例“1号雷达信号偏弱”）；必填“下一步动作”（示例“待现场确认连接线”）；期限选项 `[下一班前] [今日下班前] [指定时间] [暂无期限]`；交给班组 `[甲班] [乙班] [不指定]`；可选“可能隐患”；来源只读“来源：故障 · 1号雷达”；固定“保存交接事项”。手动事项摘要空保存归一化为“待跟进事项”；故障/工作来源自动带摘要。
- 首页待跟进查看进入列表，分组：未完成/即将到期/已逾期，底部已完成/已取消；显示状态文字、下一步动作、期限、来源；作废默认隐藏，仅筛选“包含已作废”显示且保持“已作废”，不改成“已取消”。
- 详情底部固定两个同宽主按钮，按业务状态：待交接=`标记已交接`+`取消事项`；已交接=`标记处理中`+`取消事项`；处理中=`已完成`+`取消事项`；已完成/已取消只读。`继续处理故障`不占底部，放 `⋮`，仅故障来源且关联故障可处理；手动/普通工作来源隐藏。继续处理创建同故障新处理记录，不自动改变交接为处理中；需另点“标记处理中”。已完成只结束交接，不把故障改已恢复。标记处理中/已完成/取消均二次确认；作废另行危险确认。状态文字+图标。

### 8. 搜索与筛选

- 顶栏“← 查找”；搜索框 placeholder `输入设备或关键词` + 漏斗；结果按最近更新时间：示例故障“1号雷达 / 信号强度偏弱 / 已结束 · 未恢复 · 待跟进”，普通工作“三号线 / 完成三号线巡检”。
- 漏斗打开筛选面板：`记录类型`、`日期范围`、`处理状态`、`出勤标记`、`包含已作废 [关]`；底部“重置”“应用筛选”。默认不含作废；开启后漏斗显示数量和“已作废”状态。搜索设备名称、别名、故障处理、普通工作、交接文字；同义词“信号弱”命中“信号强度偏弱”；别名承载用户补充关键词，不新增字段。

### 9. 设置、设备别名、出勤/排班、通知、备份恢复

- 设置分组列表：工作/提醒/数据/其他；入口“出勤与排班”“通知设置”“备份与恢复”“设备名称与别名”“关于 CODA”。
- 设备页顶栏“← 设备名称与别名 ＋”；设备行显示标准名、`别名：雷达1、R1`；分组“已停用（1）”。新增/编辑可改名、增删别名、停用/启用；停用只影响新建建议，不删历史/快照；名称/别名 trim、连续空白折叠、规范化，重复要明确错误；别名就是补充关键词。
- 当前出勤页：顶栏“← 当前出勤”（从摘要/设置进入显示“修正当前出勤”）；日期、当前班次、班次类型 `[普通班] [顶白班] [顶夜班] [自定义]`；顶班才显示甲/乙班；时间 `[08:00] 至 [18:00]`；底部“保存出勤修正”。顶夜班展示跨午夜完整日期时间；多段出勤在下方列表+添加；修改只影响后续，记录快照不改。首次无当前出勤自动默认普通班，已有（含跨午夜）复用。
- 月排班页：顶栏“← 本月排班 · 2026年8月”；白班起点甲/乙单选、确认状态“尚未确认”；班次建议（如 08-01 甲班白班、08-15 乙班白班、08-31 转班）可点。只影响未来班次；不正式考勤；未确认仍可记录且不猜班组；跨月 00:00-08:00 归上一班开始日，次日 08:00-20:00 按新月排班。
- 通知页：总开关“允许本地通知 [开]”；“系统权限：已允许”/拒绝时“打开系统设置”；提醒内容固定列表：事项到期、逾期每日最多一次、下一班前、每月排班确认；说明“提醒时间由系统自动安排”“不保证精确到分钟”。关闭只关系统通知，首页应用内提醒保留；暂无明确期限不建定时通知但打开 App 仍提醒。
- 备份恢复页：导出当前数据说明（故障、工作、交接、排班；实际备份还含出勤、设备/别名、草稿、已作废），按钮“导出备份”；恢复说明通知设置不变、文件未加密，按钮“选择备份文件”。恢复步骤：选择→校验→数量预览→自动保护当前数据→二次确认“确认替换本机数据”；不做合并。恢复中看到 `PREPARED` 一律安全备份回滚；失败/中断原数据不隐藏式删除。

## 通用异常、加载和可用性

- 自动保存故障/长文本；离开不弹阻塞确认；失败保留内存内容，显示具体错误+重试；详情显示最近保存状态但不占主操作区。App 重启可从首页草稿恢复；加载失败保留本地草稿+重试。
- 加载保留页面结构、局部指示器；空态解释并给下一步动作；数据库/备份校验/权限失败显示具体原因；网络不可用非阻塞（离线 MVP）。作废/替换恢复/清空需二次确认，取消/失败/系统中断回到安全状态。
- 图标按钮无障碍描述；状态文字+图标；触控 >=48dp；长文本换行不截断关键状态；支持字体放大；键盘弹出时输入框和底部按钮保持可见或可滚动到。

## UseCase/查询映射（UI 规格未写名称，以下与技术设计 v1.0 契约对照）

按钮/动作到接口：

- 首页：进入页/切换自然日/本次出勤 -> `HomeQueryUseCase.observe(HomeQuery)`；首次首页先 `AttendanceUseCase.ensureDefaultForDate(today)`；修正出勤 -> `AttendanceQueryUseCase.observeForDate(date)` + `AttendanceUseCase.update/save/setCurrent`；去确认排班 -> `ShiftScheduleQueryUseCase.observeMonth(month)` + `ShiftScheduleUseCase.confirmMonth/updateFutureSlot`。
- 快速故障：保存草稿/自动保存 -> `FaultUseCase.createDraft`（首次）/`saveDraft`（DRAFT patch）；设备建议 -> `DeviceUseCase.observe(includeInactive=false)`；进入详情 -> `FaultQueryUseCase.observeDetail(faultId)`。
- DRAFT/处理：开始处理 -> `FaultUseCase.startProcessing`（复用 DRAFT 行）；处理中字段自动保存 -> `updateProcessing`；标记待验证 -> `markPendingVerification`；待验证继续 -> `resumeProcessing`；继续处理故障（交接更多菜单） -> `continueProcessing(faultId)`；结束 -> `finishProcessing(processingId, FinishProcessingInput)`；取消本次处理 -> `cancelProcessing`；故障/处理作废 -> `voidFault` / `voidProcessing`（仅 ENDED/CANCELED 处理允许）。详情读 -> `FaultQueryUseCase.observeDetail` / `observeProcessing`。
- 普通工作：保存 -> `WorkLogUseCase.createManual`；详情/列表 -> `WorkLogQueryUseCase.observeDetail/observeList`；编辑 -> `updateManual`；作废 -> `WorkLogUseCase.void`。
- 交接：保存/编辑 -> `HandoverUseCase.create/update`；标记已交接 -> `markHandedOver`；标记处理中 -> `markInProgress`；已完成 -> `complete`；取消事项 -> `cancel`；作废 -> `void`；列表/详情 -> `HandoverQueryUseCase.observeList/observeDetail`。详情继续处理额外调用 `FaultUseCase.continueProcessing`，不改交接状态。
- 搜索/筛选 -> `SearchUseCase.search(query, SearchFilters)`（含 `includeVoided`；默认 false）。
- 设备名称/别名 -> `DeviceUseCase.observe/create/rename/addAlias/removeAlias/setActive`。
- 当前出勤 -> `AttendanceQueryUseCase.observeForDate` + `AttendanceUseCase.save/update/setCurrent/ensureDefaultForDate`。
- 月排班 -> `ShiftScheduleQueryUseCase.observeMonth` + `confirmMonth/updateFutureSlot`。
- 通知 -> `NotificationSettingsUseCase.observe/setEnabled/permissionState/openSystemSettings`。
- 备份导出/恢复 -> `BackupUseCase.export/inspect/replace`；恢复预览应直接用 `BackupPreview`，不由 UI 再查询猜测派生结果。

### 接口缺口（视觉稿不可自行发明）

- UI 规格要求“关于 CODA”页，但技术契约未列 About 查询/UseCase（若只静态文案可在 UI 层固定；版本/许可证数据接口未定义）。
- UI 要求接报时间编辑、设备最近使用建议、普通工作补充字段展开；技术契约通过 `FaultDraftPatch`/`ManualWorkPatch`/`DeviceUseCase.observe` 可承载，但字段结构未在 UI 规格直接命名，视觉稿应标“由对应 patch/input 承载”，不要新增字段。
- UI 提到“保存失败具体错误、重试、PREPARED 回滚、权限拒绝”等异常状态；契约已有 `AppError`（StorageFull/DatabaseFailure/ValidationFailure/BackupFormatInvalid/PermissionDenied/Conflict），但没有独立的 retry/query 接口，重试应重复原 UseCase/重新订阅。
- UI 要求通知调度状态；技术契约仅总开关/权限状态，无每条提醒查询或精确时间接口，视觉稿不应加时间配置入口。
- UI 的“记录类型/处理状态/出勤标记”筛选字段与 `SearchFilters` 对齐；“最近故障/待跟进/草稿”均应由 `HomeUiState` 聚合查询提供，不能各自发明 repository。

## 约束核对

- DRAFT、IN_PROGRESS、PENDING_VERIFICATION、ENDED、CANCELED 必须文字+图标区分；DRAFT 详情占位写“草稿处理（尚未开始）”，不可写“暂无处理记录”。
- CANCELED 是可见业务终态；VOIDED/voidedAt 只作隐藏标记，详情筛选后显示“已作废”，不可将其当状态按钮。
- 未结束处理/故障有未结束处理不可直接作废；取消和作废是不同动作。
- 交接底部双主按钮按四态渲染；继续处理故障仅故障来源且在更多菜单；手动/普通工作来源隐藏。
- 默认出勤 08:00-18:00 仅本机无任何当前出勤时创建，跨午夜当前出勤复用；跨午夜 `workDate` 归出勤开始日。
- 首页自然日/本次出勤内联刷新；通知只非精确调度，不展示精确闹钟权限；备份不加密且不覆盖通知偏好；PREPARED 回滚安全备份；手动摘要空显示“待跟进事项”；设备别名承载补充关键词。
